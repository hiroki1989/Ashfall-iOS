# 役割と運用

主担当PMO + Coding + Art + QA の4役。利用可能な同時実行枠は親を含め4枠のため、通常はPMO・Coding・Artの3枠で制作し、QAは完成物が揃ってから起動する。UIの見た目はArtが仕様を提案し、Unity上のUI実装はCodingが担当する。ゲームデザインの判断はPMOが担い、常設の追加役を増やさない。

## 作業の流れ

1. PMOがユーザー要望を短い受け入れ条件に変換し、STATE.mdの未完了を確認。
2. 小さい変更はPMO自身が実施。独立した実装とアートがあればそれぞれ委任。
3. 委任はcollaboration.spawn_agentを使用。原則fork_turns="none"で対象パス・担当ロール・受け入れ条件・必要な状態のみ渡す。別のユーザー所有チャットは作らない。
4. 各担当は指定ファイルだけ編集。関連.meta、インポーター設定、ART_GUIDE.mdなど仕様・プロンプト記録の担当も割り当てる。共有ファイルを変更する必要があればPMOへ知らせ、担当調整を待つ。
5. Artがアセットを完成・検査し、パスと仕様をCodingへPMO経由で渡す。Codingは実際の表示・操作に接続。
6. QAが統合成果のテストと画面確認を実施。修正は再現条件を担当へ返す。
7. PMOがビルド結果、未解決、ユーザー向け説明を確認しSTATE.mdを更新。

## トークンを節約するルール

- エージェントは常時起動しない。調査・編集を重複させない。
- 同一役のエージェントは同じ依頼内で再利用する。完了後は止める。
- 全履歴をforkしない。必要なファイルだけrgで探す。巨大ログはエラー周辺と末尾だけ。
- 毎回の報告は原則15行以内。コード全文や生成画像データは報告しない。
- 全テストは統合後に一度。修正があった範囲だけ再検証し、根拠なく繰り返さない。
- 数値的なトークン予算はユーザー指定時だけ設定する。モデルは現在の設定を継承し、勝手に変更しない。
- UIや画像の品質判断に画像を使う。コードだけで見た目が完成したと判断しない。

## 委任テンプレート

```
役割: Coding / Art / QA
プロジェクト: <絶対パス>
読むもの: AGENTS.md、Development/STATE.md、Development/TEAM.md、担当ロール
目的: <一つの成果>
担当ファイル: <排他的な編集範囲。調査だけなら明記>
受け入れ条件: <2〜4項目>
入力・依存: <必要なパスと事実だけ>
完了報告: 変更ファイル / 結果 / 検証 / 未解決。15行以内。
他担当のファイルやSTATE.mdを編集しない。
```
