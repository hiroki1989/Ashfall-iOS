# TwoView 候補生成

独立した立体メッシュと既存の承認済み画像を入力する。防具は前/後、武器は左/右を atlas の左右半分に配置する。元 GLB と元 PNG は読み取り専用。平面カードは拒否する。候補はこのディレクトリの `qa/` にのみ出力し、商品用 Resources へ登録しない。

`prepare_atlas.py` は透明余白を可視輪郭で裁断し、最近傍の不透明色で背景を埋める。全 alpha=255 の atlas と各絵の配置座標 JSON を保存する。`project_blender.py` は元メッシュを既定上限32,000面へ軽量化してからUVを再計算し、実寸境界から両絵の可視範囲へ割り当てる。各面に一方向だけを選ぶ。防具の側面は `--armor-side front-majority` で前絵を側面奥行きの85%まで使い、後端に一箇所の境界を置く。`neutral` も比較できる。各候補の正面/側面/背面 PNG と元/出力面数・UV 範囲の report.json を出す。

2026-10-21 実行: Kestrel Field Helmet の独立 Hunyuan GLB と前後原画で `helmet-candidate-v3.glb`、`helmet-render-v3/` を生成。587,586面、UV範囲外0、atlas alpha最小255。側面の二重模様は初回より減少したが、後端の黒白帯と原画からの形状差が残るため不採用。`helmet-render-v2/` は側面を無地金属へ逃がした比較版。銃は対応する独立造形と両側の承認済み入力が揃っておらず、`gun-atlas.png` は既存側面画像を二度パックした投影入力試験だけである。商品登録や完成判定の根拠にはしない。

追加軽量化検証: `helmet-candidate-lod32k.glb` は587,586面から32,000面、66.0MBから6.1MB。`helmet-render-lod32k/` の正面/側面/背面はUV範囲外0で大きな形状崩れなし。ただし側面後端の黒白帯と商品原画との形状差は残るため不採用。

正面/側面/背面 QA は、画像の輪郭・各ディテールと実形状の位置、二重模様、境界、透過空白を目視する。UV数値と alpha 検査だけで採用しない。
